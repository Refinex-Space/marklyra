# Git 同步架构

MarkLyra 把 Git 作为笔记库的版本与同步层：识别或初始化仓库，管理分支和远程，提交、拉取、推送，
查看差异与历史，并在冲突时提供三方合并工具。交互参照 IntelliJ IDEA 的 Git 集成，按笔记场景做了简化。

## 分层

```
React 壳（features/git）──invoke──▶ Rust 宿主（src-tauri/src/git）──spawn──▶ 系统 git
      ▲   纯 TS 算法（model/diff、merge、log-graph）          │
      └──────── 事件：marklyra:git-changed / git-progress / workspace-files-changed
```

- **执行**：调用本机安装的 `git`（需 2.25 或更高）。不引入 libgit2，用户已有的凭据管理器、SSH 密钥、
  hooks、`.gitconfig` 都照常生效。进程不经过 shell；Windows 下不弹控制台窗口；有超时、可取消、
  输出有上限；同一仓库的写操作串行执行。
- **授权**：每个命令只接收 `workspaceId`，由宿主解析为当前窗口已授权的文件夹，再定位所在仓库。
  界面传入的相对路径、修订、分支名、远程名和 URL 都会重新校验；`ext::` 等能执行命令的传输方式会被拒绝。
  写入文件只有一处：合并结果。它只能写当前确实处于冲突状态的文件，会拒绝符号链接，并采用临时文件加原子替换。
- **契约**：`apps/desktop/src/services/git.ts` 是 TS 与 Rust 共用的唯一接口定义。错误以 `[code] 消息`
  的形式返回，界面据此给出对应的后续操作，例如认证失败时打开凭据设置，存在冲突时打开冲突面板。
- **差异与合并**全部在前端计算：
  - 行级差异用 histogram 锚点，必要时退回有上限的 Myers。
  - 行内差异按词切分，CJK 按单字切分。
  - 三方合并用 diff3 分块。
  - 提交图按泳道布局。

### Git 视图

- **提交**：左侧是更改列表，每项有勾选框，可按目录分组，冲突单独列出。下方是提交信息框，支持修改上一次提交、
  从模板生成提交信息，Ctrl+Enter 提交，Ctrl+Shift+Enter 提交后推送。右侧实时显示所选文件的差异。
- **日志**：
  - 左栏按分支筛选。
  - 中间是虚拟滚动的提交列表：提交图、引用标签（HEAD、本地、远程、标签）、作者、时间、短哈希；
    可按信息、哈希、作者、时间、文件过滤。
  - 右栏是提交详情和更改文件，双击文件打开差异。
  - 右键提交可以复制、与工作区比较、签出、新建分支或标签、拣选、还原、重置。
- **储藏**：保存当前更改（可选包含未跟踪文件），并可应用、取回或删除已有储藏。
- **仓库**：Git 版本与路径、仓库根目录、跟踪分支、远程列表（每个都可测试连接）、提交身份、代理检测结果。

### 差异与合并

- 差异视图支持并排和统一两种布局，以及行内高亮、忽略空白、折叠未更改内容（可逐段展开）、
  F7 / Shift+F7 在更改之间跳转。行尾符或 BOM 有变化时会单独提示。超长文件分块渲染，屏幕外的块不参与布局。
- 合并工具分三栏：左为你的版本，中为结果，右为他们的版本。
  - 两栏之间的槽里有 »、«（采用）和 ×（忽略）按钮。同一处冲突两侧都采用时，保留两边内容，顺序按点击先后。
  - 结果栏的每一块都可以手动编辑或撤销。
  - 不冲突的更改自动应用，也可以点“应用所有不冲突的更改”。
  - 仍有未解决的冲突时点“应用”，会先请你确认。
  - 写回时保留原文件的 BOM 和行尾符。
  - 变基时 Git 的 ours / theirs 含义与合并相反，界面统一按“你的 / 他们的”展示。

## 同步机制

一次同步依次执行三步：

1. 提交全部本地更改（可关闭；提交信息由模板生成）。
2. 获取，并按设置的更新方式整合远程更改（合并、变基或仅快进；默认自动储藏本地更改）。
3. 推送。分支还没有上游时，自动推送到同名远程分支并建立跟踪。

- **触发**：手动（按钮、菜单）、定时、打开文件夹时、保存后约 90 秒。后三种只在开启“自动同步”后生效。
  连续失败时退避，间隔最多放大到 4 倍。
- **文档安全**：手动操作会先保存当前文档。自动同步遇到未保存的文档时直接跳过，不会替你保存。
  工作区文件变化后会触发外部变更检查：未修改的文档自动重新载入，已修改的文档显示提示。
- **冲突**：默认停下来打开冲突面板。也可以设为同一处冲突时优先保留本地或优先采用远程，
  这两种设置只影响真正冲突的位置，不冲突的修改始终合并。
- **网络**：
  - 自动模式依次使用 Git 配置中的 `http.proxy`、HTTPS_PROXY 等环境变量、系统代理（Windows 的 Internet 设置、
    macOS 的网络配置）。也可以指定自定义代理，或强制直连。
  - 代理连接失败时可以自动改为直连重试一次。
  - SSH 远程可以选择也走代理（通过 ProxyCommand），但不会覆盖你已有的 `core.sshCommand` 或 SSH 配置。
  - 不会扫描本机端口来猜测代理。
- **凭据**：优先使用系统已配置的 Git 凭据管理器。也可以在设置里为某个主机保存访问令牌：令牌存放在系统钥匙串中，
  只在执行时通过环境变量（`GIT_CONFIG_*`）传给 Git，不会出现在命令行参数、仓库配置或错误信息中。
  `GIT_TERMINAL_PROMPT=0` 保证不会卡在交互式输入上。

## 验证

```sh
pnpm exec vitest run apps/desktop/test/git-*.test.ts
pnpm exec playwright test -c playwright.desktop.config.ts tests/desktop-e2e/git.spec.ts
cargo test -p marklyra-desktop --lib git::     # 需要本机 git；Windows 先嵌入 comctl32 清单
cargo test -p marklyra-desktop --lib menu::
```

Rust 集成测试会在临时目录里真实运行 git，覆盖：初始化、按路径提交、分支、日志过滤、各冲突阶段、
合并与变基冲突、拣选与还原、储藏，以及对临时裸仓库的推送、更新与同步。

浏览器测试用替身代替原生命令，只验证界面流程，不能代替真实 WebView 和网络环境的验证。
代理、SSH 代理、系统钥匙串需要在目标平台上手动验证。
