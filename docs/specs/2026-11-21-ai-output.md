# AI 回复的 Markdown 与离线图表

## 现状与目标

在 AI 侧栏读一条包含对照表、命令和流程图的回答时，用户需要能看清结构，取用单个代码示例，并回到历史会话看到相同内容。改动前，MessageContent 使用共享的有界 Markdown 解析器，但将标题画为段落，列表项统一画作圆点，表格显示竖线，frontmatter 产生空段落。代码中的文件名还可能变成工作区链接。原始消息已经支持整条复制，任务评论已有表格和列表实现。

## 验收与实施

1. 共用只读 Markdown 块展示。标题有层级，有序列表保留起始值，嵌套列表与只读任务项可辨，引用聚组，YAML 保留原文。表格对齐、内联代码与链接可读，宽表仅在表内横滚。
2. 围栏显示语言，允许键盘复制正文、切换换行。为明确识别的常见语言提供有界静态着色。未知语言、未闭合的围栏和大段输出均保留可复制的原文。
3. 在已有运行资源源提供隔离图表页。只处理闭合、可见、符合预算的 Mermaid 源，在独立页面加载仓库自带 Mermaid。固定安全配置，无远程取图与原生 IPC，无模型代码执行。显示静态图、源码和放大预览；失败提示与原文在同一块内。
4. 原有会话格式、权限和文档链接规则沿用。用稳定的块键保留复制/换行状态；图形布局更新时贴底用户继续跟随，离底用户继续阅读。对大消息优先显示完整文本，限制派生 DOM。
5. 运行 AI 正文单元、实际 ACP 分片的桌面浏览器回归、任务 Markdown 既有测试、类型检查、资源打包与桌面构建。通过本地模拟智能体使用 ego-browser 实际操作。

## 评审裁决

| 视角 | 采纳意见 | 依据 |
| --- | --- | --- |
| 产品 | 局部横滚、两种复制、恢复时重绘，图表仅用于智能体回复 | 侧栏空间有限，工具与用户输入也调用 MessageContent |
| 架构 | 在产品现有 Markdown 和运行资源目录上扩展；避免为高亮加载编辑器 | 仓库有完整 Mermaid，CodeMirror 模式依赖全套编辑器 |
| 安全 | 图表不进入宿主 DOM；独立 CSP、消息通道、体积和生命周期限制 | 宿主有 IPC，编辑器原有图表配置允许 HTML 标签 |
| 测试 | 分阶段断言流式输出，核对复制的真实参数，覆盖宽表、无效图表及历史消息 | 原用例只对最终内联文本做断言 |


## 已实现的显示边界

- 表格支持列对齐、单元格中的链接与行内格式、转义竖线及列表内缩进表格。方向键可在聚焦的宽表内横滚。遇到超出表头的行，保留该行的 Markdown 原文。正文表格按表头列数与正文行数限制为 4096 个单元格。
- 静态词法着色覆盖 JavaScript、TypeScript、Python、Shell、JSON 和 diff 的常见标记。超过 20,000 个 UTF-16 码元的代码直接显示源码。局部复制取自围栏内部的原始范围，包含末尾换行。
- 独立图表页一次接收一个专属消息端口，在已有运行资源源加载本地 Mermaid。宿主只接收静态图片及尺寸，预留宽高，避免图片解码时打断阅读。自动绘图限于 12,000 个 UTF-16 码元、300 行以内的闭合图表，主题由应用提供。渲染失败和包含 Mermaid 配置指令的图表显示源码。
- 显示预算独立于会话存储。单条消息超过 96,000 个 UTF-16 码元、2,000 行或 8,000 个受计数的标记字符时，保留全文并退回纯文本。范围内的流式回复按围栏和列表边界复用已完成片段。

## 验证入口

- `pnpm check`、`pnpm lint` 检查类型、模块边界、引擎与构建资源，以及单元回归。
- `pnpm prepare:runtime`、`pnpm --filter @marklyra/desktop build` 生成本地图表页和桌面前端。
- `pnpm exec playwright test -c playwright.desktop.config.ts ai.spec.ts tasks.spec.ts -g 'rich answer|dark sidebar scrolls|descriptions and comments render Markdown|environment variable|AI context, mentions'` 用 Chromium 和 WebKit 操作真实面板，ACP、剪贴板及会话存储使用本地测试宿主。
