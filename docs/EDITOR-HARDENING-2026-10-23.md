# 编辑器稳定性与性能加固记录

日期：2026-10-23。起始版本：`555a025`。本轮以真实生成的编辑器资源、Chromium/WebKit 和可重复的本地夹具开展审查；所有输入均为测试文稿，未操作用户的既有文稿、应用实例或配置。

## 实现与评测边界

- `editor-core` 管理纯 TypeScript 事务、选区、差量历史和 SourceMirror。`editor-markdown`、`editor-view` 是独立编辑器的解析与 DOM 投影路径。它们的微基准不能当成桌面完整编辑器性能。
- 桌面主要使用 `editor-runtime`：隔离页面运行受版本与摘要校验的编辑器资源，原引擎维护模型、输入和历史；运行时生成可核验的变更凭据，宿主 SourceMirror 将规范文本变更映射回保留 BOM、混合换行和原始拼写的源文稿。
- 源文稿与引擎规范文本是两套坐标。正常操作出现“无法确定原始源码位置”时，应补齐实际选区、节点身份和转换结果的证明，不能删除歧义检测或用重写全文消除错误。
- React 负责生命周期和宿主界面；Tauri 负责文件、原生剪贴板和恢复存储。浏览器中的真实编辑器与模拟的原生 IPC 分别记录，不以浏览器测试代替系统输入法、WKWebView 或 WebView2 验收。

## 操作覆盖

除既有专项用例外，新矩阵将段落、ATX/Setext 标题、有序与嵌套列表、引用、任务、表格、嵌套强调、删除线、代码、普通/引用链接、脚注、公式与 HTML 邻接内容，与 LF／BOM+混合换行组合。用真实键盘执行文本输入、回车续写、反复撤销重做、历史分支继续输入和源码模式往返。检查源文稿字节、光标后续行为、页异常及 SDK 错误。

剪贴板测试区分 DOM `ClipboardEvent`/`DataTransfer`、宿主右键入口和系统原生剪贴板。合成剪贴板与模拟原生 IPC 可以验证语义、所有权和时序，不能证明系统剪贴板兼容性。

自动保存与恢复验证覆盖：连续输入延长空闲期限、候选输入阻止保存、保存中继续编辑、旧文档写入完成、丢失检查点回复的精确重放、保存与清理的时序、重启发现以及显式恢复。当前桌面 App+真实 runtime 的相关既有测试 84 项通过，原生 recovery-store 24 项通过。

最终静态与单元检查：`pnpm check` 通过，包含类型、依赖边界与 143 个文件的 1,810 项测试；`pnpm build` 成功；运行时资源变换测试 67 项通过。全仓 `pnpm lint` 存在 19 项既有格式/SVG 可访问性错误；逐文件摘要核对确认相关文件与起始版本一致，本轮变更文件单独检查通过。没有顺带格式化或修改这些范围外文件。

## 性能实测

同进程旧新版本微基准保留脚本、原始采样和基线提交。12,000 行批量标题三轮：原版 9.35–10.60 秒，修复后 11.39–39.30 毫秒。30,000 个反斜杠：原版 2.19–2.95 秒，修复后 0.29–0.46 毫秒。200,000 个未闭合链接起点：原版 1.05–1.21 秒，修复后 7.79–11.81 毫秒。这些是独立核心/解析路径的限定工作负载，不是桌面交互端到端成绩。

实际 runtime 的 10 KiB、100 KiB、1 MiB 夹具在两浏览器上均完成 SDK.load 返回、真实键入、10 KiB 合成粘贴和精确 flush，未丢源文稿；load 返回时间不等于所有异步预览都已绘制。1 MiB 混合夹具有 20,521 个根块、252,103 个元素，属于高节点密度负载。基线采样中 Chromium/WebKit 键入墙钟中位数约 144/215 毫秒；WebKit 粘贴+flush 约 7.0 秒。采样期间存在其他回归负载，样本量小，不把这些数值当成稳定的尾延迟指标。

进一步的只读计时定位到 WebKit 原引擎延迟 `selection.scrollAdjust()` 内的 `content.scrollTop` 同步读取，单次约 3.88 秒；全文序列化也是输入热路径的重要开销。该证据能定位同步布局和全量遍历问题，但还不足以证明跳过滚动、缓存几何或省略同步是正确修复。本轮不以关闭滚动/源码保护来制造性能提升。

最后一次构建后的六个 runtime 夹具再次全部完成，源文稿精确、错误数组为空，运行前后资源指纹一致。该轮未并行运行其他浏览器回归。Chromium 1 MiB 键入中位数约 109 毫秒、粘贴+flush 约 0.95 秒；WebKit 分别约 177 毫秒、9.92 秒。与前两轮的负载环境不同，不能据此做稳定回归幅度判断；可以明确的是，本轮没有消除该高节点密度 WebKit 延迟。

## 编辑器行为基线

本轮对照确认，Element 选区粘贴、异步粘贴历史、表格列元数据和长文档布局存在既有缺口。当前原生线性序列化、空选区文本读取、节点查找和表格修复需要保留。输入身份一致仅支持复用明确范围的历史静态证据，不能据此推断新宿主运行行为相同。

## 尚不能宣称的结果

本轮没有执行 Windows 真机、真实 WKWebView/WebView2、系统中文/日文/韩文输入法候选、系统剪贴板和实际崩溃重启的完整验收。高节点密度大文档仍存在可测延迟。现有证据不支持“全部 Markdown 和平台达到 100 分”或“已穷尽所有边界”的结论。

既有 `structural-commands.spec.ts` 的 `-K02` 仍明确标记原版已知差异：带子孙列表的 outdent 后，两个相邻 UL 在重新解析时合并，列表分组身份与即时模型不同。源文稿保真断言通过，但这项结构差异不能按完全一致处理；两浏览器保留其限定的预期失败。
